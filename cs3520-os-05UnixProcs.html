A process is a program in execution.

Every process has a process id called a pid.

A running process can create one or more 'child' processes. There is a parent/child relationship between the processes.

Every process keeps track of its parent process id via a ppid (parent process id) field in the process control block (PCB).

There is a process called init that is the ancestor of all processes in the system. It is the first process that is created when the system boots up.

To compile a C/C++ program, we use the g++ compiler.

g++ -o myProgram main.cpp

  • g++ is the compiler command.

  • -o is an option that tells the compiler to create an executable file with the name myProgram. List the contents of the current directory to see the new executable file.

  • myProgram.cpp is the source code file. Often, I will use *.cpp as a wildcard to compile all of the C++ source code files in the current directory.

g++ -o myProgram *.cpp

When you run a program from the terminal, you can pass information into the program via command line arguments. For example:

./myProgram arg1 arg2 arg3

Here, arg1, arg2, and arg3 are pieces of data (C-strings) that are passed into the program myProgram.

In C/C++, the main function can be defined to take two parameters: argc and argv.

#include <iostream>

using namespace std;

//argc is the number of command line arguments- c for count
//argv is an array of c strings with the command line arguments- v for values
int main(int argc, char* argv[])
{
    cout<<"Writing all " <<argc<<" arguments to the screen"<<endl;

    //write all the arguments (argv[0] is the name of the program)
    for(int i = 0;i < argc;i++)
    {
        cout<<argv[i]<<endl;
    }

    return 0;
}

argc- a count of the number of command line arguments passed into the program (including the name of the program itself)

argv- a collection of values that are passed into the program.

argv[0] is always the name of the program itself

Process API

In a C/C++ program you can request some information about the process that is running.

getpid() is a system call that returns the process id (pid) of the current process.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    //get the process id
    int myPid = getpid();

    //print the process id
    cout<<"The process id of this process is "<<myPid<<endl;

    return 0;
}

You can also get the parent process id using getppid().

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    pid_t myPid = getpid(); //my id
    pid_t parentPid = getppid(); //my parent's id

    //print the process id of the parent and child
    cout<<"The process id of this process is "<<myPid<<endl;
    cout<<"The process id of the parent is "<<parentPid<<endl;

    return 0;
}

fork() will create a brand new process from a running program (which is also a process) and ready it for scheduling.

The process that creates it is the parent, the new process is the child.

The child process is an exact copy of the process image with one exception, the child process has a different pid.

In the parent's version of the process image, fork() will return the new pid of the child.

In the child's version of the process image, fork() will return the value 0.

Each process will continue executing the same program after the fork(), but they will be executing independently of each other.

Each process has a PC (program counter) that keeps track of where the process is in the program.

After a fork(), both the parent and child processes will have their own PC that points to the next instruction to execute (albeit in different process images).

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    //create a new process, put it in the ready queue
    if(fork() == 0) //this is the child process
    {
        cout<<"I am the child"<<endl;
    }
    else //non-0 means this is the parent
    {
        cout<<"I am the parent process"<<endl;
    }
    return 0;
}

How do we use fork() to do two things at once?

We could write all of the code in two separate blocks in an if/else branch but makes it like writing two programs in a single file.

A better option is to replace a process image with another right after a fork().

The exec() family of functions does this to 'execute' a program in a child.

execvp(executableFileName, arrayOfArguments)

The executable code in a process will be replaced by the executable code specified in another executable and the PC will be set to start inside the main() of the new program.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    cout<<"Testing the execvp() system call"<<endl;

    //these are the arguments for the new process
    char* args_argv[] = {"args", "mark", "mahoney", 0};

    //replace this process image with a new one in the same dir, ./args
    execvp("./args", args_argv);

    //execlp("./args", "args", "george", "w", "bush", 0);
    //execlp("ls", "ls", "-l", 0);

    //this shouldn't be printed because the image has been replaced
    cout<<"This should not be printed"<<endl;

    return 0;
}

We can combine fork() and exec() to create a new process and run a different program in that process.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    cout<<"Testing the execvp() system call"<<endl;

    //command line arguments
    char* args_argv[] = {"args", "mark", "mahoney", 0};

    //fork and run args in the new process
    if(fork() == 0)
    {
	//child runs new process
        execvp("./args", args_argv);
    }
    else
    {
	//parent picks up here
        cout<<"This is the parent"<<endl;
    }
    return 0;
}

Often, we want one process to wait for another to finish before it continues.

This is what the wait() system call is for. It will block the calling process until one of its child processes exits.

wait(&status)

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    cout<<"Testing the execvp() system call"<<endl;

    //command line arguments
    char* args_argv[] = {"args", "mark", "mahoney", 0};

    int status;

    //fork to create a new process
    if(fork() == 0)
    {
	//child runs the new program
        execvp("./args", args_argv);
    }
    else
    {
        //wait for the child to complete
        wait(&status);

        //then print out parent message
        cout<<"This is the parent"<<endl;
    }
    return 0;
}

The status variable is used to return information about how the child process exited.

waitpid() does about what you would expect it to do.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    cout<<"Testing the execvp() system call"<<endl;

    //command line arguments
    char* args_argv[] = {"args", "mark", "mahoney", 0};

    int status;

    //fork and store the child process id
    int childID1 = fork();
	
    //if this is the child
    if(childID1 == 0)
    {
	//run the new program
        execvp("./args", args_argv);
    }
    else
    {
	    int childID2 = fork();
	    
	    if(childID2 == 0)
	    {
		//run the new program
	        execlp("ls", "ls", "-l", 0);
	    }
	    else
	    {
		//wait for the child to complete based on the child ID
		waitpid(childID1, &status, 0);
		waitpid(childID2, &status, 0);

		cout<<"This is the parent"<<endl;
	    }
    }
    return 0;
}

sleep() will suspend the execution of a process for a certain amount of time.

The process is placed in the blocked state and will not be scheduled to run until the sleep time has expired.

The process is not guaranteed to begin executing immediately after the sleep time has expired.

It will be placed in the ready queue and will be scheduled to run according to the scheduler's algorithm.

sleep(seconds)

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    cout<<"Testing the execvp() system call"<<endl;

    //command line arguments
    char* args_argv[] = {"args", "mark", "mahoney", 0};

    int status;

    //create a new process
    if(fork() == 0)
    {
	//put child to sleep
        sleep(2); //sleep for 2 seconds

        //run a new program
        execvp("./args", args_argv);
    }
    else
    {
	//parent will wait for child to complete (block)
        wait(&status);

        //parent message
        cout<<"This is the parent"<<endl;
    }

    return 0;
}

A zombie process is when a child process has completed but the parent process has not yet called wait() to collect the child's exit status.

The parent still thinks the child is alive and the child process is in a 'zombie' state.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    //create a new process
    if(fork() == 0)
    {
	//kill the child while parent is asleep
        cout<<"I am a child process about to exit"<<endl;
        exit(0); //create a zombie
    }
    else
    {
	//cause the parent to sleep
        sleep(2);

        //child is gone
        cout<<"This is the parent, child is a zombie"<<endl;
    }
    return 0;
}

An orphan process is when a parent exits before the child has completed.

The child process is then adopted by the init process.

#include <iostream>
#include <unistd.h>

using namespace std;

int main(int argc, char* argv[])
{
    //create a new process
    if(fork() == 0)
    {
	//cause the child to sleep
        sleep(2);

        //when child wakes up, parent is no longer there
        cout<<"I am an orphan child process"<<endl;
    }
    else
    {
	//kill the parent while the child is sleeping
        exit(0); //create an orphan
    }
    return 0;
}
