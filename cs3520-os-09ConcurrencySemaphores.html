Semaphores are a synchronization and mutual exclusion tool provided by the OS that do not require busy waiting.

The section of train track is like a critical section of code.

Only one train should be allowed on the track at a time.

Semaphore Basics

A semaphore is an integer variable and a queue of threads.

struct Semaphore 
{
    int count; 
    queue<Thread> procQ;
};

Apart from initialization, a semaphore can only be accessed by using two mutually exclusive operations:

wait(sem)
signal(sem)

The wait() operation decrements the semaphore's count.

If the count is negative, the thread executing wait() is blocked and added to the semaphore's queue.

void wait(Semaphore &sem) 
{
    sem.count--;
    if (sem.count < 0) 
    {
        //place the thread in the queue
        //block the thread
    }
}

The signal() operation increments the semaphore's count. If the count is not positive (negative or zero), a thread is removed from the semaphore's queue and unblocked.

void signal(Semaphore &sem) 
{
    sem.count++;
    if (sem.count <= 0) 
    {
        //remove a thread from the queue
        //ready the thread (put in the ready state)
    }
}

wait() and signal() must be mutually exclusive.

Only one thread can be inside a call to wait() or signal() at a time.

Semaphore Observations

s.count >= 0: The number of threads that can call wait() without being blocked.

s.count < 0: |s.count| is the number of threads that are in the queue and currently blocked and waiting on the semaphore.

The counter must be initialized to a non-negative value (0 or greater).

Semaphores for Mutual Exclusion

Semaphore s(1);

T(i)                        T(j)
while(true)                 while(true) 
{                           {
    wait(s);                    wait(s);
    //critical section          //critical section
    signal(s);                  signal(s);
    //remainder section         //remainder section
}                           }

So, for general mutual exclusion, a semaphore initialized to 1 is used.

Semaphores for Synchronization

We can also use a semaphore for synchronization.

Semaphore s(0);
T(i)                      T(j)
while(true)               while(true) 
{                         {
    cout<<"Hello ";           wait(s);
    signal(s);                cout<<"World";
}                         }

How would one print out a full name (first, middle, last) using three threads and semaphores?

T(i)                 T(j)                 T(k)
while(true)          while(true)          while(true)
{                    {                    {
    cout<<"Mark ";      cout<<"Robert ";      cout<<"Mahoney"<<endl;
}                    }                    }

POSIX Semaphores

A POSIX semaphore is created with the sem_init() function.

int sem_init(sem_t* sem, int pshared, unsigned int value);

sem_t* sem is a pointer to a semaphore object.

int pshared is an integer that indicates whether the semaphore is shared between processes or threads.

unsigned int value is the initial value of the semaphore.

A thread can acquire a semaphore by calling sem_wait() and release it by calling sem_post().

int sem_wait(sem_t* sem);

int sem_post(sem_t* sem);

Example 1 Mutual Exclusion

#include <iostream>
#include <unistd.h>
#include <pthread.h>
#include <semaphore.h>

using namespace std;

//this function will be called when a thread is created
void* foo(void* arg);

//global variable shared between all threads
int num = 0;

//the number of threads we want to create
const int numThreads = 10;

//shared semaphore (global variable shared between all threads)
sem_t mutex;

int main()
{
    //array of thread identifiers, one for each thread
    pthread_t threads[numThreads];

    //array of return values of foo function
    void* thread_result[numThreads];

    //init the semaphore to the value 1, only one thread at a time in a critical section
    sem_init(&mutex, 0, 1);

    cout<<"Creating threads"<<endl;

    //create the threads
    for(int i = 0;i < numThreads;i++)
    {
        pthread_create(&threads[i], 0, foo, 0);
    }

    //wait for the thread to finish
    for(int i = 0;i < numThreads;i++)
    {
        pthread_join(threads[i], &thread_result[i]);
    }

    cout<<"All threads finished"<<endl;

    return 0;
}
//--
void* foo(void* arg)
{
    //request to enter the critical section
    sem_wait(&mutex);
    
    //critical section

    //print the value of num
    cout<<num<<endl;

    //increase the value of the shared num by one
    num++;

    //done with the critical section
    sem_post(&mutex);

    //remainder section

    //return a null pointer (required for methods called from new threads)
    return 0;
}

Example 2 Mutual Exclusion

#include <iostream>
#include <unistd.h>
#include <pthread.h>
#include <semaphore.h>

using namespace std;

void* square(void* arg);

sem_t mutex;
int num = 0;
const int numThreads = 10;
int squares[numThreads];

int main()
{
    pthread_t threads[numThreads];
    void* thread_result[numThreads];

    //init the semaphore to the value 1, only one thread at a time in a critical section
    sem_init(&mutex, 0, 1);

    cout<<"Creating threads"<<endl;

    //create the threads
    for(int i = 0;i < numThreads;i++)
    {
        pthread_create(&threads[i], 0, square, 0);
    }

    //wait for the thread to finish
    for(int i = 0;i < numThreads;i++)
    {
        pthread_join(threads[i], &thread_result[i]);
    }

    cout<<"All threads finished"<<endl;
    cout<<"Printing the squares:"<<endl;

    for(int i = 0;i < numThreads;i++)
    {
        cout<<squares[i]<<endl;
    }

    return 0;
}
//--
void* square(void* arg)
{
    sem_wait(&mutex);

    //critical section
    squares[num] = (num + 1) * (num + 1);
    num++;

    sem_post(&mutex);

    return 0;
}

Example 3 Synchronization

#include <iostream>
#include <unistd.h>
#include <pthread.h>
#include <semaphore.h>

using namespace std;

//these functions will be called when a thread is created
void* hello(void* arg);
void* world(void* arg);

//shared semaphore (global variable shared between all threads)
sem_t sync_sem;

int main()
{
    //thread identifiers
    pthread_t threads[2];

    //return value
    void* thread_result[2];

    //init the semaphore to the value 0
    sem_init(&sync_sem, 0, 0);

    //create the first thread
    pthread_create(&threads[0], 0, world, 0);

    //give the 'world' process a 2 second head start
    sleep(2);

    //create the second thread
    pthread_create(&threads[1], 0, hello, 0);

    pthread_join(threads[0], &thread_result[0]);
    pthread_join(threads[1], &thread_result[1]);

    return 0;
}
//--
void* world(void* arg)
{
    //this will guarantee that 'world' will be printed last
    sem_wait(&sync_sem);

    cout<<"World!!!"<<endl;

    //return a null pointer
    return 0;
}
//--
void* hello(void* arg)
{
    cout<<"Hello ";

    //this lets the other thread know that it can continue
    sem_post(&sync_sem);

    //return a null pointer
    return 0;
}

Producer-Consumer Problem

Producer/Consumer is when there is a thread that produces things and another thread or processes that consume those things.

This is a common interaction in concurrent programming and can be solved using semaphores.

int buffer[100000]; //assuming a really big fixed buffer for simplicity
int in = 0;
int out = -1;

void append(int v)
{
    buffer[in] = v;
    in++;
}

int take()
{
    out++;
    int temp = buffer[out];
    return temp;
}

What can go wrong here?

T(i)- producer                 T(j)- consumer
while(true)                    while(true)
{                              {
    int item = produceItem();      int y = take();
    append(item);                  //use y for something
}                              }

Semaphore mutex(1); 
Semaphore not_empty(0); 

T(i)- producer                  T(j)- consumer
while(true)                     while(true)
{                               {
    int item = produceItem();     wait(not_empty);
    wait(mutex);                  wait(mutex);
        append(item);                   int y = take();
    signal(mutex);                signal(mutex);
    signal(not_empty);              
}                               }

Any number of producers and consumers can safely use this code to produce and consume items without any race conditions.

Now, let's solve the problem with a bounded buffer.

We need to add a semaphore to keep track of how many items are in the buffer and how many empty slots are in the buffer.

Semaphore mutex(1);
Semaphore not_empty(0);
Semaphore not_full(N); // N is the size of the buffer   

T(i)- producer                 T(j)- consumer
while(true)                    while(true)
{                              {
    int item = produceItem();      wait(not_empty);
    wait(not_full);                wait(mutex);
    wait(mutex);                     int y = take();
        append(item);              signal(mutex);
    signal(mutex);               signal(not_full);
    signal(not_empty);             
}                              }

Dining Philosophers Problem

The dining philosophers problem is a classic synchronization problem that illustrates the challenges of resource allocation and deadlock.

Imagine that there are five philosophers who only eat and think sitting at a table with five chopsticks.

Each philosopher needs two chopsticks to eat. The philosophers alternate between thinking and eating.

This problem illustrates the difficulty of allocating resources among threads without deadlock and starvation.

I'll start by creating a semaphore for each chopstick and initializing it to 1 (indicating that the chopstick is available).

Semaphore chopstick[5] = {1, 1, 1, 1, 1};

T(i) - //philosopher i values, 0-4
while(true)
{
    think();
    wait(chopstick[i]); // pick up left chopstick
    wait(chopstick[(i+1)%5]); // pick up right chopstick
    eat();
    signal(chopstick[i]); // put down left chopstick
    signal(chopstick[(i+1)%5]); // put down right chopstick
}

What can go wrong here?

One solution to this problem is to only allow four philosophers to attempt to eat at once.

This can be achieved by using a semaphore to limit the number of philosophers that can attempt to eat at the same time.

Semaphore chopstick[5] = {1, 1, 1, 1, 1};
Semaphore allowToEat(4); // only 4 philosophers can attempt to eat at once

T(i) - philosopher i values, 0-4
while(true)
{
    think();
    wait(allowToEat); // wait for permission to eat
    wait(chopstick[i]); // pick up left chopstick
    wait(chopstick[(i+1)%5]); // pick up right chopstick
    eat();
    signal(chopstick[i]); // put down left chopstick
    signal(chopstick[(i+1)%5]); // put down right chopstick
    signal(allowToEat); // signal that we are done eating
}

This code will ensure that at most four philosophers can attempt to eat at the same time, which will prevent deadlock.

  • Rendezvous / Barrier Two threads must both reach a meeting point before either can continue. Good for showing bidirectional signaling.
Semaphores: aArrived(0), bArrived(0)

T(i):                    T(j):
cout << "A ready"        cout << "B ready"
signal(aArrived)         signal(bArrived)
wait(bArrived)           wait(aArrived)
cout << "A proceeds"     cout << "B proceeds"
  • Strict Alternation (Turnstile) Force two threads to strictly alternate execution.
Semaphores: turnA(1), turnB(0)

T(i):                    T(j):
wait(turnA)              wait(turnB)
cout << "A"              cout << "B"
signal(turnB)            signal(turnA)

Output will always be: A B A B A B...

  • Multiplex (Limited Capacity) Allow at most N threads into a "room" at once (like a parking lot).
Semaphore: spots(2)  // only 2 allowed at once

T(i), T(j), T(k):    // 3 threads competing for 2 spots
wait(spots);
cout << "entered";
think(); // represents being in the room
cout << "leaving";
signal(spots)

Using semaphores is a difficult art.

The calls to signal() and wait() may be spread out to many different threads and functions.

It can be difficult to understand how the semaphores are being used and to ensure that they are being used correctly.

Usage must be correct in all of the threads. Even one incorrectly written thread can cause the entire system to fail.

When there are multiple developers working on the same codebase, it can be difficult to ensure that everyone is using the semaphores correctly and consistently. The probability of mistakes is high.
